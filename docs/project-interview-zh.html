12 / FOLLOW-UP
Likely follow-up questions

把追问引向可验证的设计决策

每个回答都从结论开始，再给机制、失败场景和测试证据。

Q1

为什么不用数据库，反而选择 JSONL？

因为采集器是短生命周期进程，追加文件最可靠、最容易审计。当前单机场景收益大于查询成本；规模触发后再引入索引层。

Q2

SSE 为什么不会在重连时丢事件？

服务在每条新连接上先发送完整 reset，再发送 ready，之后才进入 trace 增量；客户端按事件 ID 合并。

Q3

拓扑中的推断会不会误导用户？

原始 Trace 永远是事实源；没有直接证据的原子明确标记 INFERRED，而且投影不回写协议数据。

Q4

如何保证多平台会话不会串数据？

会话键使用 source::workspaceId::sessionId；工具再用 toolUseId 配对，子智能体关系使用 parentId。

Q5

为什么 28 条连线始终保留？

连线表示执行契约，事件表示运行证据。固定结构让早期状态、完整态与回放态使用同一空间坐标，减少认知跳变。

Q6

观测系统自身失败怎么办？

Hook 错误写 stderr 但继续放行 Agent；坏 JSONL 行隔离；SSE 重连补偿；Worker 失败回退主线程。
